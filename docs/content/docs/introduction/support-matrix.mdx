version. Find your path below before you rely on it. The general feature matrix
was last reviewed against the repositories on
**September 22, 2026**.

Other review dates:

- **Axiom Cloud engines, capabilities and targets** were reviewed on
  November 4, 2026 against the production service configuration.

- **Distribution and platforms** were checked on November 13, 2026 against the
  published release assets.
- **Run your first app** was run end to end on October 21, 2026 with published
  CLI 0.149.1 and signed web UI host 0.6.12 on macOS arm64.
- The backend, frontend and database quickstarts were checked on October 15,
  2026 with published CLI 0.149.0 and web UI host 0.6.12 on macOS arm64.
- Detailed database and advanced-language qualifications keep their own
  baselines in [Capability boundaries](/reference/capability-boundaries).

## Status definitions

| Status | Meaning |
| --- | --- |
| **Available** | Usable on the stated path. This does not imply a stable major release or universal production certification. |
| **Alpha** | Implemented and testable; APIs or workflows may change. |
| **Experimental** | A bounded implementation exists; compatibility, parity or distribution is incomplete. |
| **Coming soon** | No supported runnable workflow is available. |

## Distribution and platforms

The Axiom CLI release is **0.151.0** (November 12, 2026). It pairs with web UI
host 0.8.0.

| Platform | Status | CLI 0.151.0 | Boundary |
| --- | --- | --- | --- |
| macOS arm64 (Apple silicon) | Alpha | Archive published | Installer script, Homebrew or manual download. All walkthroughs are checked here. |
| Linux amd64 | Experimental | Archive published | Installer script only. Needs glibc 2.36 or newer (for example Debian 12 or Ubuntu 24.04). Includes a managed PostgreSQL 17 validator. Walkthroughs, extractors and UI hosts are not checked on Linux. |
| Linux arm64 | Experimental | Archive published | Same as Linux amd64. |
| macOS on Intel (x86_64) | No build | None | The installer detects the platform but finds no archive. |
| Windows | No build | None | No native build; the installer rejects Windows. WSL2 is not checked. |
| Alpine and other musl Linux | No build | None | The installer requires glibc. |

Installer platform detection does not establish artifact availability. Other

| Acore language server (`acore-lsp`) | 0.1.4 | Bundled in the CLI; standalone build for macOS arm64 |

## Cloud and applications

Connected accounts, projects, releases, environments, tests, observability and
the Cloud Dashboard are **Alpha** and need their configured services. Axiom
Studio, Acode and Axiom Marketplace are **Coming soon**.

Project environment secret management is **Alpha** in the deployed Dashboard
and through the `axiom secrets` commands of CLI 0.151.0 and later (CLI 0.149.1
has no `secrets` command). Protected local and Cloud consumption is
**Experimental** in the matching source preview on macOS arm64 with native
ActionHost and server WASM. The source web frontend uses delegated backend
operations. Native mobile runtime parity and container or Worker consumption
are unqualified. Published CLI 0.149.0, 0.149.1 and 0.151.0 and hosts 0.6.12
and 0.8.0 do not include the protected consumption qualification. See
[Secrets at runtime](/backend/runtime-secrets).

[Cloud secrets](/cloud/secrets) describes the deployed inventory, candidate
review, runtime access and activity workflow, and secret environment
protection and expiry. The [Secrets commands](/tooling/secrets-cli) reference
covers `axiom secrets`.

## Local database workflow

CLI 0.149.0 and later, including 0.149.1, provide versioned run, migrate,
rollback, status, history, comparison and typed application storage.
PostgreSQL needs a reachable server and a matching validator; the Linux CLI
archives include a PostgreSQL 17 validator. SQLite uses a local file. Browser
previews simulate storage and history; they do not perform native migrations.
See [Capability boundaries](/reference/capability-boundaries) for constraints
outside the checked local path.

## Managed project databases

Dashboard database preferences, managed storage provisioning and resource
lifecycle controls, including qualified access rotation, are **Alpha**, checked
on October 20, 2026. Customers select SQLite or PostgreSQL; allocation depends
on location, capacity and entitlement.
[Hosted migrations](/cloud/hosted-migrations) for managed SQLite and
PostgreSQL are **Alpha**, checked on October 20, 2026 with a source build of
the CLI; the commands need CLI 0.151.0 or later.
[Hosted runtime connections](/cloud/connect-a-server) from Cloud Run servers
to managed SQLite and PostgreSQL are **Alpha**, checked on October 24 and 25,
2026 with source builds of the CLI and runtime; the commands need CLI
0.151.0 or later.
[Managed application authentication](/authentication) (signup, password
sign-in, sessions, token exchange, roles and permissions) is **Alpha**,
checked on October 25, 2026 on managed SQLite and PostgreSQL. Verifying its
tokens in a deployed Axiom server (`axiomAuth`) needs a runtime release and
is **Coming soon**. The Dashboard **Authentication** page administers
authentication.
Public paid checkout is **Coming soon**. The
`axiom project resources` commands need CLI 0.151.0 or later, and
`axiom project create` runs without a terminal when you pass `--name` and
`--slug`. See
[Managed resources](/cloud/project-resources) and the local
[database workflow](/database).

Axiom Cloud signup is invite-only and new managed databases are limited to
admitted projects. Daily backups and Owner restores are turned on for selected
projects only. Limits and regions are on [Limits](/cloud/limits) and
[Regions](/cloud/regions). Prices are published at general availability.

## Axiom Cloud engines and capabilities

Each managed database profile admits capabilities one by one. **Admitted**
means the capability passed its production checks on that profile.
**Candidate** means it is built but not admitted. A capability can be
admitted and still be off for customers until it is turned on; the last
column says what you can use.

| Capability | SQLite (libSQL) on Turso, managed | PostgreSQL 17 on Neon, managed | SQLite (libSQL) in your own Turso account | Status for customers |
| --- | --- | --- | --- | --- |
| Hosted migrations | Admitted | Admitted | Candidate | Alpha, invited accounts |
| Runtime connections from your servers | Admitted | Admitted | Candidate | Alpha, invited accounts |
| Managed authentication | Admitted | Admitted | Candidate (authentication stays in an Axiom store) | Alpha, invited accounts |
| Dashboard table and SQL editor | Admitted | Admitted | Candidate | Alpha, invited accounts |
| Backups, restore and archive | Admitted | Admitted | Not offered | Coming soon for all projects; on for selected projects |
| Advanced authentication (OAuth apps, MFA, passkeys, hooks) | Admitted | Admitted | Candidate | Alpha, invited accounts |
| Preview branches | Admitted | Admitted | Not offered | Alpha, selected projects |
| Conversion to PostgreSQL | Admitted (as the source) | Not applicable | Candidate | Alpha, selected projects |
| Moves between pools and regions | Candidate | Admitted | Candidate | Alpha, selected projects |

Unsupported: native SQLite files in Axiom Cloud, PostgreSQL row-level
security in managed schemas, browser or device database sync, and a
transaction that spans your own Turso database and the Axiom authentication
store. The Sydney region, Microsoft sign-in, the Supabase, Auth0 and Clerk
presets and Sign in with Apple are not offered.

Engine versions are set by the providers. The CLI's PostgreSQL validator and
the hosted PostgreSQL transaction profile target PostgreSQL 17.

## Advanced authentication and database placement

These capabilities are built and checked in production. Each stays off for
every environment until it is turned on. **Alpha** capabilities are available
to invited accounts; those marked for selected projects are turned on for
selected projects only during the Alpha. The CLI commands that use them need
CLI 0.151.0 or later; `@axiomcore/auth-web` 0.2.0 is not yet published. See the
[upgrade guide](/cloud/upgrade-guide#opt-in-to-the-new-features).

| Capability | Status | Boundary |
| --- | --- | --- |
| [OAuth applications and the OIDC issuer](/authentication/oidc) | Alpha | Authorization code with PKCE only; not OpenID Certified |
| [Authenticator apps, recovery codes, step-up and assurance guards](/authentication/mfa) | Alpha; assurance guards Coming soon | Assurance guards need an `axiomAuth` provider on native or Linux container targets; not on Workers |
| [Passkeys](/authentication/mfa#passkeys) | Alpha | On the application's own web origin only |
| [Phone verification and SMS codes](/authentication/phone) | Coming soon | Pro only, your own Twilio account; tested against a simulated Twilio API, real SMS delivery not qualified |
| [Event webhooks and claim hooks](/authentication/hooks) | Alpha | HTTPS endpoints you host; no code runs in Axiom |
| [Microsoft sign-in](/authentication/social) | Coming soon | Microsoft Entra ID work and personal accounts |
| [Sign in with Apple](/authentication/social#sign-in-with-apple) | Coming soon, not available yet | Tested only against a simulated Apple service; cannot be turned on |
| [Supabase Auth, Auth0 and Clerk presets](/authentication/third-party) | Coming soon | Token exchange; hosted sign-in through Auth0 or Clerk OIDC; no Supabase hosted sign-in |
| [Local auth emulation and settings promotion](/authentication/local-emulation) | Alpha | Password, email code, mock OIDC, refresh and logout only |
| [Auth policy releases and impact checks](/authentication/policy-releases) | Alpha | Impact is per role |
| [Your own Turso database](/cloud/turso-connections) | Coming soon | Application data only; authentication stays in an Axiom store; no transaction spans both |
| [SQLite to PostgreSQL conversion](/database/project-upgrades) | Alpha, selected projects | Pro only; application unavailable until you redeploy; every user signs in again; no rollback after activation |
| [Pool, dedicated and region moves](/cloud/database-placement) | Alpha, selected projects | Managed PostgreSQL; libSQL moves not qualified; dedicated pools not sold |
| [Preview branches](/cloud/branches) | Alpha, selected projects | Lifetime at most 7 days; parents up to 100 MB for sanitized and libSQL branches |

Qualified targets for these capabilities are listed in
[Qualified targets for Axiom Cloud](#cloud-qualified-targets).

## Project intelligence CLI

[Project intelligence commands](/tooling/intel) are **Experimental** in source
builds that expose `axiom intel --help`. They cover activity, telemetry, project
settings, pipeline runs, pull requests and security inspection. Published CLI
availability and production qualification are not established by this preview.
