---
title: Policies and runtime behavior
description: Declare cache and retry intent globally or for an individual endpoint.
---

Service contracts can declare cache and retry policy. The runtime applies only
the behavior implemented for the selected client target; inspect the generated
contract and validate the target before relying on it.

Private `serverCache` policies are a separate host boundary. Their canonical
identity includes the exact plan/schema/codec, normalized input and verified
identity/permission partition. Each read authenticates and runs guards, even on
a hit. A shared fill has independent waiter cancellation and a fixed action
deadline capped at 30 seconds. `invalidateOn` observes accepted command success;
it does not attest an external transaction commit. See [server integrations](/reference/server-integrations).

## Global policy

```acore
policies(
  cache: CachePolicy(strategy: CacheStrategy.staleWhileRevalidate, ttlSeconds: 3600),
  retry: RetryPolicy(
    maxAttempts: 3,
    retryOnCodes: [502, 503, 504],
    retryOnTimeout: true,
    backoff: ExponentialBackoff(
      initialDelay: "500ms", maxDelay: "10s", multiplier: 2.0, useJitter: true
    )
  )
)
```

## Endpoint override

```acore
endpoint get_profile(method: GET, path: "/profile") {
  response(type: Json)
  cache(strategy: CacheStrategy.cacheFirst, ttl: 5m)
  retry(attempts: 2)
}
```

An endpoint-level value is the narrow override for that endpoint. Do not infer
an override from the HTTP method.

## Reusable policies and defaults

Use `defaults` for concise project-wide settings and `policy` for a named,
reusable declaration:

```acore
defaults {
  cache(strategy: CacheStrategy.networkFirst, ttl: 30s)
}

policy reads {
  cache(strategy: CacheStrategy.cacheFirst, ttl: 2m)
  retry(
    attempts: 3,
    onStatus: [502, 503, 504],
    onTimeout: true,
    backoff: Exponential(initial: 250ms, max: 2s, multiplier: 2.0, jitter: true)
  )
}

endpoint listProjects(method: GET, path: "/projects") {
  response(type: Json)
  use(reads)
}
```

`use(policy: reads)` is the equivalent fully named form. `Fixed(...)` and
`Linear(...)` provide the other typed backoff constructors. Durations such as
`250ms`, `2s`, and `2m` are compiler-checked values.

An explicit endpoint policy takes precedence over a variant cache policy,
which takes precedence over project defaults. A reused policy expands into the
endpoint declaration; it is not an ordered runtime call. Defining the same
singleton twice, including through `use`, is an error. Policy cycles and
unknown names are errors. Inspect effective settings and their origins with
`axiom explain axiom.acore --provenance`.

## Cache strategies

| Authoring value | JSON value | Contract intent |
| --- | --- | --- |
| `CacheStrategy.networkOnly` | `network_only` | Do not satisfy the request from the contract cache. |
| `CacheStrategy.cacheFirst` | `cache_first` | Use a valid cached value before network. |
| `CacheStrategy.networkFirst` | `network_first` | Prefer network and use the target's implemented fallback behavior. |
| `CacheStrategy.staleWhileRevalidate` | `stale_while_revalidate` | Permit an existing value while a refresh is attempted. |

`ttlSeconds` is required by `CachePolicy`. Storage, eviction, privacy, and
background-refresh behavior remain target/runtime concerns.

## Retry and backoff

`RetryPolicy` defaults to three attempts, retry codes `502`, `503`, and `504`,
and timeout retries. Backoff implementations are fixed, linear, and
exponential. Review retries for non-idempotent operations and declare security
or idempotency requirements where appropriate.

Policy declarations are not server enforcement and do not replace rate limits,
timeouts, circuit breakers, or observability in the backend.


## Owned operations

Logical resource `operationPolicy` declarations preserve existing client and `serverPolicy` meanings. Total deadlines cover queues, attempts, and host backoff; trusted providers attest safety independently. See [operation policies and composition](/acore-language/owned-operations#logical-resource-policies).
