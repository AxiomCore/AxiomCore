Modern app development is plagued by **"Glue Code"**. 

Tools like **OpenAPI (Swagger)**, **GraphQL**, and **tRPC** are fantastic at defining the *shape* of data (types). However, they completely fail to define the *behavior* of the API. 

### The Problem: Behavioral Drift
If a backend developer wants an endpoint to be cached for 60 seconds, or to retry 3 times on a `502 Bad Gateway` error, they have no way to enforce this across clients. 

The iOS team writes a retry loop in Swift. The Web team writes one in Axios/React Query. The Android team forgets to write one entirely. This results in **Behavioral Drift**—where the exact same API acts completely differently depending on the platform.

### The Maintenance Tax of "Fat CodeGen"
To solve integration, developers use Code Generators (like `openapi-generator`). But **generated code is still code**. 

<Callout type="warn" title="The High Cost of Fat SDKs">
A typical OpenAPI-generated SDK for a medium-sized project can exceed **10,000+ lines of Dart or TypeScript**. You are forced to compile, ship, and maintain massive serialization files, HTTP wrapper logic, and error-parsing blobs that you didn't even write.
</Callout>

---

### The Axiom Paradigm: Thin SDKs + Generic Runtime

AxiomCore solves this by replacing generated code with a **pre-compiled Generic Runtime** (Rust for native, Wasm for Web).

Instead of generating HTTP fetch logic, Axiom generates a **Thin Proxy**. When you call `sdk.users.getUser()`, the SDK simply forwards an instruction to the native Runtime. The Runtime executes the network call, handles the retries, checks the embedded SQLite/Sled cache, validates the schema using `rod-rs`, and returns the exact data.

### Cryptographic Trust
Beyond behavior, Axiom enforces security. Every `.axiom` contract is cryptographically signed using Ed25519 keys via Axiom Cloud. If an attacker intercepts your API schema and attempts to modify validation rules, the Runtime will detect the broken signature and refuse to boot.
