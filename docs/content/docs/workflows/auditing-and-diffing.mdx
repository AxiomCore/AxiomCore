---
title: Auditing and semantic diffing
description: Compare authored contracts, locked dependencies, and typed packages at their semantic boundary.
---

Text diffs show source edits. Axiom semantic diffs describe the resulting
contract or package impact after evaluation and normalization.

For a complete frontend, backend, or combined workspace, Axiom Inspector adds
application-wide facts, relationships, authority, runtime sessions, impact,
and source evidence. Start with the [Axiom Inspector guide](/inspector).

## Contract source and lock

```bash
axiom diff axiom.acore --format changelog
axiom diff before.acore after.acore --format semantic
```

Supported output formats are `changelog`, `semantic`, `text`, and `atom`. The
one-source form compares with the local lock state; the two-source form compares
explicit inputs.

## Locked UI contracts

```bash
axiom contract diff before.ui.lock.json after.ui.lock.json
axiom contract verify
```

Contract lock review is the right boundary for operation, audience, projection,
and artifact-integrity changes consumed by an Acore UI.

## Typed packages

```bash
axiom packages diff before.axiom after.axiom
```

Package diff classifies kind-specific changes such as target reduction, required
theme roles, component prop/slot changes, and capability increases. Breaking or
permission-increasing changes can require an explicit approval named by the
diff result.

## Review evidence

Keep the before/after immutable identities, semantic output, approvals, and test
results together. A diff is evidence about declared semantics; it is not proof
that arbitrary backend code or separately distributed extension bytes are safe.

## Whole-application snapshots and impact

Create canonical evidence before and after a material application change:

```bash
axiom inspect snapshot . --output before.evidence.json
# make the reviewed change
axiom inspect snapshot . --output after.evidence.json

axiom inspect diff before.evidence.json after.evidence.json \
  --fail-on breaking,permission-increase

axiom inspect impact Product.price_label \
  . --against after.evidence.json
```

Inspector compares semantic identities across UI, state, contracts, backend,
packages, extensions, authority, targets, and optional normalized runtime
evidence. Its impact traversal is bounded and reports completeness; it is not a
claim about unavailable external implementation code.

See [Changes, impact, and CI](/inspector/changes-impact-and-ci) for snapshot
validation, change classes, runtime comparison, and pull-request evidence.
