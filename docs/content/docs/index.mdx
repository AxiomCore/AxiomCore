**AxiomCore connects the frontend, backend and database of an application
through typed, versioned contracts.** A contract describes the operations,
data, validation and behavior a consumer can rely on. You can keep a supported
backend and frontend, or write your API, UI and database schema in **Acore**,
AxiomCore's declarative language.

## How the pieces connect

```mermaid title="Acore source or an existing backend becomes a contract that clients, UI, database and tools use"
flowchart LR
  A[Acore source] --> C[.axiom contract]
  B[Existing FastAPI or Go backend] --> C
  C --> D[Client SDKs]
  C --> E[Acore UI app]
  C --> F[Database migrations and storage]
  C --> G[Axiom Inspector]
  C --> H[Axiom Cloud releases]
```

1. **Source.** Write `.acore` files, or extract the contract from a FastAPI or
   Go service.
2. **Contract.** The Axiom CLI builds a `.axiom` contract you can review, diff,
   test and lock.
3. **Consumers.** Web, React, Flutter and Swift clients call the API through
   generated SDKs. An Acore UI app uses the same contract. Database contracts
   drive SQLite or PostgreSQL migrations and typed storage.
4. **Tools.** Axiom Inspector shows relationships and the impact of a change.
   Axiom Cloud stores shared releases.
