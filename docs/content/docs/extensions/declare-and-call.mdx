This page is the reference for how an application names an extension, calls
its exports from Acore, says which state an action may change, and requests
permissions and budgets. For a first walkthrough, see
[Build an extension](/extensions/build).

## Declare the extension once

Write the `AxiomDeps.toml` alias once. Every export of the extension becomes
callable as `<alias>.<export>`:

```acore title="main.acore (excerpt)"
module example.extension.samples.ui

use extension pricing

app Samples { route "/" => Home }

page Home {
  state cart {
    subtotal_cents: Int = 12000
    discount_cents: Int = 0
    total_cents: Int = 12000
  }

  action apply = pricing.apply_discount(cart.subtotal_cents) writes cart { discount_cents, total_cents }

  view {
    SafeArea {
      Text(value: cart.total_cents)
      Button(label: "Apply discount", on_press: apply)
    }
  }
}
```

Rules:

- `use extension <alias>` must end its line. A trailing comment is allowed;
  any other token after the alias is an error (`AUI082`).
- The alias must be a key of `[extensions]` in `AxiomDeps.toml` and cannot be
  an Acore keyword. An alias uses lowercase letters and digits, with single
  `_` between them, and starts with a letter (`pricing`, `pricing_ts`,
  `ext2`); it is at most 122 characters. Any other alias, for example
  `my-ext`, `MyExt`, `_ext` or `my__ext`, fails when the manifest is read
  with `AXIOM_EXTENSION_ALIAS_INVALID` and the reason.
- Calling an export the extension does not have is `AUI077`. The message lists
  the exports that exist.
- The editor completes exports after `pricing.` and shows the export's
  interface on hover.

### Exports come from the extension

`exports` in `AxiomDeps.toml` is optional. When you omit it, Axiom takes the
export list in this order:

1. the selected `interface` file, if the extension has one;
2. the list the last source build recorded in `.axiom/AxiomDeps.lock`, if the
   extension sources have not changed since that build;
3. otherwise resolution fails with `AXIOM_EXTENSION_EXPORTS_UNDERIVED`.

A source build compiles the guest, reads its exports and records them in the
lock. Rust takes them from the `#[export]` methods of the `#[extension]` impl,
and Python from the `@extension.export` functions. TypeScript dispatches
exports dynamically, so a TypeScript extension must keep `exports` (or name an
`interface`). A legacy Rust `axiom_extension()` factory must keep `exports`
too.

```toml title="AxiomDeps.toml"
[extensions.pricing]
language = "rust"
source = "logic/pricing.rs"
targets = ["web", "server"]
```

The lock entry is never trusted over the guest. If the sources changed since
the entry was recorded, readers fail with `AXIOM_EXTENSION_EXPORTS_STALE`, and
the next build records the new list. `axiom run` builds every extension first,
so a changed list is picked up on the next run. `--locked` resolution and
`--frozen` runs refuse a stale entry (`AXIOM_EXTENSION_EXPORTS_LOCK_MISMATCH`).
Exports carry no authority.

Removing an `exports` list that equals the derived list changes the canonical
manifest digest but not the binding, the interface or the authority.
`axiom dependencies check --against <old AxiomDeps.toml>` names that change:

```text title="Output of axiom dependencies check --against AxiomDeps.before.toml (digests shortened)"
Valid AxiomDeps.toml v2: AxiomDeps.toml
Canonical manifest: 6fc7ec7f...
Canonical manifest changed from 3c314ca1...:
  - extension `pricing`: exports now derived; the removed list [apply_discount, quote] equals the derived exports, so the binding and authority are unchanged
0 contract(s), 0 Axiom package(s), 6 extension(s), 0 build environment(s).
```

## Say which state an action changes

An action that calls an extension can declare the state fields the call may
change with a `writes` clause:

```acore title="Concise and block actions"
action apply = pricing.apply_discount(cart.subtotal_cents) writes cart { discount_cents, total_cents }

action recalc() writes cart { total_cents } {
  pricing.apply_discount(cart.subtotal_cents)
}
```

The clause is optional. Add it when the extension patches state that the
action does not otherwise show. A clause lists at least one field, names each
scope once per action and each field once per clause. It may continue on the
following lines. Paths may be dotted (`cart.totals.net`).

The compiler compares the clause with the write permissions of every extension
the action calls, including calls inside branches:

| Situation | Code | Severity |
| --- | --- | --- |
| A declared field is not granted to any called extension | `AUI084` (`AXIOM_WRITES_NOT_GRANTED`) | Error |
| A granted write is not covered by a clause that is present | `AUI085` (`AXIOM_WRITES_UNDECLARED`) | Warning |
| A clause on an action that calls no extension | `AUI086` (`AXIOM_WRITES_WITHOUT_EXTENSION`) | Error |
| A malformed clause (no field list, a repeated field or scope) | `AUI083` | Error |

Coverage is by field path. A declared `a.b` is within a granted `a`. A declared
`a` when only `a.b` is granted is broader than the grant and is `AUI084`; the
message names the granted paths to list instead.

For example, the samples' block action above declares only `total_cents`,
while `pricing` may also write `discount_cents`, so `axiom ui check` warns:

```text title="Output of axiom ui check main.acore --target web"
main.acore:16:19:AUI085: warning `pricing` may write `cart.discount_cents`, which this action's `writes` clause does not declare
```

The check uses the extension's write permissions, which may be wider than what
its code actually writes. That is why an uncovered grant is a warning, not an
error. The editor hover on the action shows the same result, and
[What an extension can do](/extensions/effect-summaries) explains how static
effect summaries relate to it.

## Request permissions

Permissions go under `[extensions.<alias>.permissions]`. Omitted permissions
are denied. There are two spellings with the same meaning.

### Shorthand

```toml title="AxiomDeps.toml"
[extensions.pricing.permissions]
ui.cart = { read = ["subtotal_cents"], write = ["discount_cents", "total_cents"] }
network.payments = { origin = "https://payments.example.test", methods = ["GET", "POST"] }
secrets = ["payment"]
```

| Key | Meaning |
| --- | --- |
| `ui.<scope>` | UI state of one scope: `read`, `write`, `dispatch`, `subscribe` (field lists). Same as `ui-state.<scope>`. |
| `network.<operation>` | An HTTPS call named `<operation>` to one `origin` with the listed `methods` (`DELETE`, `GET`, `HEAD`, `PATCH`, `POST`, `PUT`). |
| `secrets` | Names of secrets the extension may use. The extension receives an opaque handle, never the secret value. |

Shorthand lists may be in any order. The shorthand lowers to the long form, so
the canonical manifest, the authority request, the generated bindings and the
locks are byte-identical to the long form of the same permissions.

### Long form

The long form is still the canonical lowering and is still accepted:

```toml title="AxiomDeps.toml (long form)"
[extensions.pricing.permissions.contract-runtime.catalog]
query = [
    "discount",
    "price",
    "shipping",
    "stock",
]

[extensions.pricing.permissions.ui-state.cart]
read = ["subtotal_cents"]
write = [
    "discount_cents",
    "total_cents",
]
```

`axiom dependencies format --permissions long` prints any manifest in this
form, and `--permissions shorthand` in the shorter one.

`contract-runtime`, `backend-store` and `runtime` have no shorthand. Network,
storage, file, queue and secret ports can also be written as long-form
`resources` entries. Long-form lists must be sorted. You can mix forms: the
shorthand and `resources` merge into one sorted list, and only the same port
written in both forms is refused.

`axiom dependencies check` and `axiom run` print one
`AXIOM_DEPS_PERMISSIONS_SHORTHAND` hint per manifest when the shorthand can
spell long-form permissions. It is a hint, not a warning.
`axiom dependencies format` keeps the spelling you wrote.

### Canonical origins

A network origin must be written exactly as its canonical form: lower-case
scheme and host, punycode for international domain names, no default port, no
trailing slash, path, query, fragment or user name. The rule applies to both
forms.

| Written | Result |
| --- | --- |
| `https://payments.example.test` | Accepted |
| `https://Payments.example.test/` | `AXIOM_PERMISSION_INVALID_ORIGIN`: must be written canonically as `https://payments.example.test` |
| `https://bücher.example` | `AXIOM_PERMISSION_INVALID_ORIGIN`: must be written canonically as `https://xn--bcher-kva.example` |
| `http://api.example.test` | `AXIOM_PERMISSION_INVALID_ORIGIN`: plain `http` is accepted only for `localhost`, `127.0.0.1` and `[::1]` |
| `http://127.0.0.1:8080` | Accepted |
| `http://127.1` | `AXIOM_PERMISSION_OBFUSCATED_ORIGIN`: write it in dotted decimal as `http://127.0.0.1` |
| `https://*.example.test` | `AXIOM_PERMISSION_WILDCARD`: one exact origin; wildcards are not permitted |

One origin has one spelling, so it has one canonical manifest and one
authority digest.

### Permission diagnostics

| Code | Raised for |
| --- | --- |
| `AXIOM_PERMISSION_UNKNOWN_KEY` | An unknown permission key, or an unknown key inside `network.<operation>` or `ui.<scope>` |
| `AXIOM_PERMISSION_INVALID_VALUE` | A wrong type, a missing `origin` or `methods`, an empty table or list, an operation or secret name that is not an identifier, or more than 32 resource ports in total |
| `AXIOM_PERMISSION_INVALID_ORIGIN` | An origin that is not in canonical form (see above) |
| `AXIOM_PERMISSION_OBFUSCATED_ORIGIN` | IPv4 not in dotted decimal, percent-encoding, look-alike Unicode characters, invisible characters |
| `AXIOM_PERMISSION_WILDCARD` | `*` in an origin, method, secret or UI field |
| `AXIOM_PERMISSION_INVALID_METHOD` | An empty `methods` list or a method outside the list above (case-sensitive) |
| `AXIOM_PERMISSION_DUPLICATE` | A repeated method, secret or field, the same scope in `ui` and `ui-state`, or the same port in the shorthand and in `resources` |

`axiom dependencies schema` prints the JSON Schema of `AxiomDeps.toml`,
including both spellings.

## Request budgets

`[extensions.<alias>.budgets]` requests budgets beyond the defaults:

```toml title="AxiomDeps.toml"
[extensions.pricing.budgets]
maxRounds = 3
```

| Key | Range | Default | Meaning |
| --- | --- | --- | --- |
| `maxRounds` | 1 to 16 | 1 | How many times an invocation may yield effects before it completes. An async export that awaits three times in sequence needs 3. |
| `deadlineMs` | 1 to 60,000 | 1,000 | Wall-clock deadline of one invocation in milliseconds, for all of its rounds together. The host policy deadline still caps it. |

Values outside the range fail with a named diagnostic, for example
`AXIOM_AUTHORITY_MAX_ROUNDS: extension pricing budgets.maxRounds = 17 is outside 1..=16`;
they are never clamped. Only these two keys are accepted (also spelled
`max-rounds` and `deadline-ms`). Raising either one is a permission increase that needs review, like
any other. [Async exports and effect rounds](/extensions/async-rounds) explains
how to choose them.

## Deprecated forms

These forms keep working. Each one is reported so you can migrate when you
choose.

| Form | Report | Migration |
| --- | --- | --- |
| `use extension Pricing from "pricing" export "apply_discount"` | `AUI087` warning | Editor code action **Migrate to `use extension pricing`** |
| Long-form permissions the shorthand can spell | `AXIOM_DEPS_PERMISSIONS_SHORTHAND` hint | Editor quick fix "Rewrite permissions with the shorthand", or `axiom dependencies format --permissions shorthand` |
| An explicit `exports` list equal to what the guest compiles to | `AXIOM_EXTENSION_EXPORTS_DERIVABLE` hint from the source build | Remove the list |

The legacy declaration compiles to the same binding (interface digest and ABI
symbol) as the name-once form.

### Migrate a legacy declaration

The editor code action rewrites the whole application in one edit: the
declaration (usually in `main.acore`) and every `Pricing.apply_discount(` call
in every Acore file. Text inside strings and comments is not changed. Several
legacy declarations of one alias migrate together.

The action is not offered when it cannot be complete and safe:

- the project has no `AxiomDeps.toml`, so the editor cannot see the whole
  application;
- the alias already names something else in a file of the application;
- a legacy local name is used other than as `Local.<export>`, for example as a
  value;
- the alias is not a valid identifier, or is a keyword.

Renaming an export in the editor updates every Acore call bound to it (both
forms), the `export "<name>"` strings of legacy declarations and the
`exports` entry in `AxiomDeps.toml` when the manifest lists exports. It does
not rename the export in the guest source; the next build reports the
mismatch.
