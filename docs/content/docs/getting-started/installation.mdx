Install the **Axiom CLI**, then add an extractor or UI host when your chosen
path needs one. Local authoring and testing do not require a Cloud account.

## 1. Install the CLI

The 0.149.0 CLI release provides a **macOS arm64** archive. Check the
[release assets](https://github.com/AxiomCore/AxiomCore/releases/tag/cli-v0.149.0)
before choosing a platform. Linux downloads and a native Windows installer are
not included in this release. WSL2 still needs a compatible Linux executable.

On an Apple silicon Mac, download and verify the archive:

```bash title="Terminal"
mkdir axiom-install
cd axiom-install
curl -fL https://github.com/AxiomCore/AxiomCore/releases/download/cli-v0.149.0/axiom-macos-arm64.tar.gz -o axiom.tar.gz
echo '229cf5b0e6d3ff2b1dfbe7ed8138a4864eba7ddd622d9a7e97f70a1d8578a8c6  axiom.tar.gz' | shasum -a 256 -c -
tar -xzf axiom.tar.gz
mkdir -p "$HOME/.local/bin"
install -m 755 axiom "$HOME/.local/bin/axiom"
export PATH="$HOME/.local/bin:$PATH"
axiom --version
```

```text title="Expected output"
axiom 0.149.0
```

Add the `PATH` line to your shell configuration for future terminals. Remove
the temporary `axiom-install` directory after installation.

Homebrew is another macOS arm64 installation path:

```bash title="Terminal"
brew install AxiomCore/tap/axiom
axiom --version
```

The general installer is `curl -fsSL https://axiomcore.dev/install | bash`.
Its current channel selection uses older release-tag naming and may select an
older CLI. Use the verified release above for database quickstarts, which
require 0.149.0. The installer defaults to `/usr/local/bin` and may request sudo;
`INSTALL_DIR` selects another directory.

## 2. Check your environment

```bash title="Your application directory"
axiom doctor
axiom onboard
```

`doctor` reports prerequisites without writing files, logging in, pulling
contracts, or displaying credentials. `onboard` detects the application and
prints a plan. For a supported backend, `onboard --apply` can create source;
it does not upload or publish a release.

Use `axiom doctor --json --strict` for a machine-readable CI or support report.

## 3. Add the tools your path needs

| Path | Setup |
| --- | --- |
| Acore web UI | `axiom ui host install --target web --version 0.6.12 --non-interactive` |
| Existing FastAPI backend | Install its Python dependencies, then `axiom install axiom-fastapi --module` |
| Existing Go backend | `axiom install axiom-go-extractor --module` |
| Acore backend or SQLite example | No extractor is required |

The signed web host must match the CLI's supported capabilities. Host 0.6.12
was checked with CLI 0.149.0. An older installed host can fail even when both
commands are installed. See [versioning](/reference/versioning-and-deprecation)
for compiler, host, SDK, and editor compatibility.

Extractors install separately under `~/.axiom/plugins/`. FastAPI extraction
imports the application module, so keep import-time initialization safe.
Read the [extraction boundary](/core-concepts/ghost-introspection) before CI use.

## 4. Start locally or connect to Cloud

Run the [first app](/getting-started/quickstart), or choose the
[backend](/getting-started/quickstart-backend),
[frontend](/getting-started/quickstart-frontend), or
[database](/getting-started/quickstart-database) guide.

Cloud operations and release publishing require an authorized machine:

```bash title="Optional Cloud access"
axiom join you@yourcompany.com
```

The referral flow sends a code by email; a subsequent Cloud command uses it
to authorize the machine. Local authoring commands remain available without
joining the private alpha.
