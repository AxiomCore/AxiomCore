Choose an **existing frontend integration** or an **Acore-authored UI**. Both
consume a contract; they have different setup and lifecycle requirements.

## Existing framework application

Keep your application and select its supported client:

| Framework | Guide | Status |
| --- | --- | --- |
| Web / ATMX | [Vanilla web](/frontend/web) | Available |
| React / ATMX | [React](/frontend/react) | Alpha |
| Flutter / Dart | [Flutter and Dart](/frontend/flutter-dart) | Alpha |
| Swift | [Apple platforms](/frontend/swift) | Experimental; binding parity is incomplete |

For web/React, install a compatible local generator before pulling. CLI
0.149.0 has no matching automatic npm companion; the
[complete web example](/guides/fastapi-to-web#pull-the-web-client) pins and tests
`atmx-cli` 0.146.7. Qualify React separately. With that preparation and a local
contract from your backend:

```bash title="Existing frontend directory"
axiom doctor
axiom onboard --role frontend --framework atmx-web
axiom pull --contract ../backend/backend.axiom --framework atmx-web
```

Select `atmx-react`, `flutter`, or `dart` only for the matching supported path.
Keep the dependency declaration and generated lock together. Follow the
emitted integration instructions and the [integration workflow](/frontend/integration-workflow)
for initialization, authentication, errors, caching, and disposal.

## Authored Acore UI

Install the [CLI and compatible web host](/getting-started/installation), then:

```bash title="Terminal"
axiom ui init hello --target web
cd hello
axiom ui check src/main.acore --target web
axiom run src/main.acore --target web --port 5173
```

Open `http://127.0.0.1:5173`. The generated starter displays a greeting and a
Reset button. Edit the greeting in `src/main.acore`; the running app reloads.
This starter has no backend dependency. Stop it with Ctrl-C.

For a full-stack UI, keep the frontend's `type = "frontend"` manifest in its
own directory. Declare backend dependencies under `[contracts.<alias>]` in
that manifest. A backend keeps its separate `type = "backend"` manifest.
See [contract imports](/acore-language/imports-and-contracts#compiled-contracts-use-contract).

`axiom run` discovers manifests, rebuilds stale local Acore dependencies, and
maintains its development lock. Explicit lock paths are advanced overrides.
Registered sandbox modules need their compatible toolchain and verification.

## Add data, forms, and tests

Run the [persisted task app](/getting-started/quickstart) to see queries,
contract-backed form validation, mutations, typed errors, and list refresh.
Then follow the [application lifecycle](/frontend/application-lifecycle) and
[frontend testing guide](/testing/frontend-applications).

For browser-only experiments, use the playground's database task or inventory
example. [Browser preview](/database/browser-preview) explains editable source,
table inspection, and the limits of its simulated storage.

Check `android` and `ios` separately before claiming parity. Their development
paths require a compatible signed UI host and an emulator or simulator.
Generated adapter tests do not prove a mounted native application.
