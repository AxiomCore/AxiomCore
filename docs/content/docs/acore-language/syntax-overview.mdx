---
title: Syntax overview
description: The implemented lexical and structural rules of an Acore module.
---

Backend contracts use `type = "backend"` in `AxiomDeps.toml` and the named declarations described
in the [backend profile](/acore-language/backend-profile). General-purpose
Acore modules retain properties, classes, and expressions. The UI compiler has
its own application declarations. Newlines separate declarations visually;
semicolons are not part of the source grammar.

## Module declaration

Use a dotted module name when a profile needs a stable source identity:

```acore
module commerce.orders
```

The generic evaluator accepts modules without this declaration. Acore UI source
requires it because the module identity participates in the graph and artifact.

## Comments

Line comments begin with `//` and continue to the end of the line.

```acore
// Contract policy shared by all endpoints.
policies(cache: CachePolicy(strategy: CacheStrategy.networkFirst, ttlSeconds: 60))
```

Block comments are not part of the current lexer.

## Properties

In general-purpose evaluator modules, a property can have a value, a type, or
both:

```acore
name = "orders"
port: Int = 8080
optionalLabel: String? = null
```

Backend root declarations take named arguments:

```acore
project(id: "orders-api", version: "1.0.0")
```

Backend constructors also take named arguments:

```acore
// The cache argument of policies(...) or variant name(...).
CachePolicy(strategy: CacheStrategy.cacheFirst, ttlSeconds: 300)
```

There is no `new` keyword. Endpoint policy shorthand uses
`cache(strategy: CacheStrategy.cacheFirst, ttl: 5m)`.

## Objects and dynamic keys

Plain braces create a dynamic object. Bracketed keys are evaluated at runtime:

```acore
headers = {
  contentType = "application/json"
  ["x-request-id"] = "example"
}
```

Backend variants use declarations and ordinary list values:

```acore
variant mobile(include: ["public_*"])
```

## Collections

Square brackets create a list expression. Backend profile values require commas
between elements; general evaluator modules also accept whitespace separation:

```acore
codes = [502, 503, 504]
names = ["tasks", "users"]
```

Backend types use `List<T>` and `Map<K, V>`. Collection values remain ordinary
bracketed arrays and colon-separated objects:

```acore
model Index {
  names: List<String>
  counts: Map<String, Int64>
}
```

## Strings and numbers

The current parser accepts double-quoted strings, signed integers, and decimal
floats:

```acore
message = "contract ready"
attempts = 3
sampleRate = 0.25
```

Escapes are lexed inside double-quoted strings. Triple-quoted and hash-delimited
tokens are reserved by the lexer but are not part of the documented evaluated
surface yet; use ordinary strings in portable source.

## Annotations and modifiers

Annotations precede a member and may carry an object body. Modifiers precede
properties, classes, type aliases, functions, or modules where supported:

```acore
@deprecated { reason = "Use currentEndpoint" }
hidden oldEndpoint = "legacy"

open class BasePolicy {
  enabled: Boolean = true
}
```

Implemented modifier tokens are `local`, `hidden`, `fixed`, `const`,
`abstract`, `open`, and `external`. Their effect depends on the declaration and
compiler profile; do not use them as a security boundary.

## Identifiers

Identifiers begin with an ASCII letter or underscore and continue with letters,
digits, or underscores. Dots are member access except inside a module name.
Names are case-sensitive.
