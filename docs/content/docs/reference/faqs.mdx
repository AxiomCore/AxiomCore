### Is the React `sdk` proxy secure?
Yes. When you type `sdk.users.getUser()`, the Proxy object generated by ATMX captures the method call. It does not execute arbitrary Javascript or use `eval()`. It simply passes the endpoint ID and your JSON payload to the pre-compiled WebAssembly engine (`axiom_wasm_call`). The Wasm engine handles the secure network execution.

### How does Zero-JS Hydration work in ATMX?
When the ATMX script is loaded, it checks `sessionStorage` for cached payloads *before* initiating the Wasm download. If data exists, it updates the DOM context synchronously (`state: "data"`). This allows React or Vanilla Web to render the populated UI on the very first frame, completely eliminating the "Loading Skeleton" flash.

### Why do I need extractors on my machine?
Axiom's "Ghost Introspection" requires the extractors to read your raw source code (`.py` or `.go`) and convert it into an Abstract Syntax Tree (AST). By separating this into `axiom-fastapi` and `axiom-go-extractor`, the main Axiom CLI remains lightweight, and we can support new languages without updating the core tool.

### Can I use AxiomCore in CI/CD?
Absolutely. The `axiom build` and `axiom test` commands are designed to run headlessly. Because of Ghost Introspection, your GitHub Action runner doesn't even need to run `pip install` or setup a database to compile the `.axiom` contract.

### What happens if the backend changes but I don't run `axiom pull`?
Your frontend will continue to use the `.axiom` contract stored in your assets. If the backend deletes a field that the contract requires, the Rust runtime will intercept the malformed response and throw a controlled `ResponseDeserializationFailed` error. Your app will handle it gracefully via the `error` state rather than crashing with a null-pointer exception.
