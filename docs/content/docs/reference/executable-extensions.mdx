## Status and compatibility

Executable extensions are **Experimental**. The package payload is
`axiom-extension/v2`; the current guest ABI is `axiom-extension-abi` version
`1.0.0`. Supported source profiles are typed Rust, managed TypeScript/Javy, and
restricted Python 3.12 AOT/Javy. All three use the same canonical messages,
authority intersection, host broker, lifecycle, and audit identities. The
source-level command group is `axiom extensions`.
Pin package, ABI, SDK, engine, broker, target policy, and host identities in
the release provenance. None of these interfaces has a stable-major
compatibility promise yet.

The module media type is `application/wasm`. It is a separately distributed
artifact whose SHA-256 and byte length must match the package, package lock,
authority lock, and target host handoff.

## ABI lifecycle

The binary frame is canonical and starts with the `AXE1` magic value. It carries
the ABI version and one typed message. The host validates frame size, magic,
canonical encoding, request IDs, pointer ranges, and state transitions before
accepting a message.

```text
host: Negotiate -> Initialize -> Invoke
guest: Negotiated -> Initialized -> Completed | Yielded | Failed
host: Resume | Cancel -> Drain -> Shutdown
guest:            ... -> Drained -> Shutdown
```

A yielded invocation returns one bounded effect plan. The host validates and
executes its allowed effects, then resumes the same request with ordered effect
outcomes and event batches. A terminal response is accepted once. Invalid
transitions, use after shutdown, malformed frames, version mismatch, oversize
messages, and duplicate terminal replies fail closed.

Generated guests export memory and four core-Wasm functions:

```text
axiom_extension_abi_version() -> i32
axiom_extension_alloc(length) -> pointer
axiom_extension_dispatch(pointer, length) -> packed length/pointer
axiom_extension_dealloc(pointer, length) -> 1 | 0
```

These are ABI details, not a native application API. Extension authors use the
language SDK; they do not use JNI, Swift/Objective-C, or FFI pointers. Those
bridges remain trusted host implementation details on Android and iOS. A
TypeScript extension does not run in Node or a browser realm, and a Python
extension does not embed or call host CPython.

## Language SDK model

The SDK's `Extension` trait models initialization, invocation, resume,
cancellation, and shutdown. `UiSelector`, `UiPatchBuilder`, `StoreSelector`,
and `StoreTransactionBuilder` construct typed wire proposals; they do not
mutate host state directly.

```rust
// Axiom generates this readable selector from AxiomDeps.toml.
let discount = axiom_bindings::ui_checkout_write_discount_selector::<()>();

let patch = axiom_extension_sdk::UiPatchBuilder::new("checkout", revision)
    .set(&discount, axiom_extension_sdk::abi::Value::Unsigned(10))
    .build();
```

The host applies the patch only when its declared paths, type checks,
invariants, expected revision, effective authority, deadline, and lifecycle
are valid. Store transaction proposals use the same model and apply atomically
or return a conflict. SDK assertions protect generated selector consistency;
untrusted input is still revalidated by the host.

TypeScript uses `defineExtension` with generated branded selectors. Python uses
`@extension.export` with generated selector stubs. Both return the same typed
completion, effect, patch, transaction, stream, cancellation, and error shapes
as Rust. Language convenience never creates authority absent from
`AxiomDeps.toml`.

## Authority surface

Authority is declared per exact imported namespace and operation. The host
does not infer authority from source code. Every allowed action is included in
the signed request, application grant, and target policy before it becomes
effective.

| Group | Declared capabilities |
| --- | --- |
| Contract runtime | Query, mutation, command, batch, and stream operations on named services and methods |
| UI state | Read, write, dispatch, and subscribe on declared scope paths |
| Backend store | Read, write, insert, remove, action, and subscribe on declared object fields |
| Resources | HTTPS origin/method pairs, namespaced storage, rooted relative files, secret use, queues, logging, tracing, context, clocks, and secure random |

Authority also includes host-call, read-byte, write-byte, mutation, event, and
concurrent-stream budgets. A target policy can narrow a package request; it
cannot add access the package did not request. Frontend profiles deny
backend-store, secret, file, and private/internal-network authority unless an
explicit host escalation and matching signed inputs allow it.

## State, effects, and stream rules

An invocation receives only authorized snapshots. It can return bounded
effects, UI patches, backend transaction proposals, and emitted events. Patches
support set, unset, increment, append, compare-and-set, and declared action
dispatch. The host records the extension and resource identity, expected and
resulting revision, paths, decision, and redacted details.

Subscription handles are opaque and scoped to one application, extension
instance, generation, and permission. Event delivery is ordered, bounded, and
cancellable. The host may report dropped events or coalesce a subscription to
its latest event; subscriptions do not grant unrelated reads or writes.

## Security and lifecycle limits

Native hosts use the Wasmi interpreter with no ambient WASI, no start function,
no unreviewed imports, bounded memory and fuel, recursion limits, a bounded
worker, and finite teardown. The browser host uses a dedicated Worker and
terminates it on deadline or cancellation. Module identity, ABI version,
application, extension, effective authority, target, engine, and limits are
all part of the cache identity.

The foreign-island path is deliberately different: a runtime-dependent Web UI
bundle runs in an opaque-origin iframe with a private typed message channel. It
is Web-only, visibly foreign, and cannot access the parent document, browser
credentials, direct network APIs, or undeclared host methods. It is not a
native mobile WebView feature.

No sandbox proves a guest's business logic is correct. Review the semantic
permission diff, application-level authorization, data invariants, release
policy, and target deployment configuration in addition to module identity.

## Source-authored application flow

An application author maintains one Acore UI, one permission/dependency file,
and normal Rust, TypeScript, or Python source in any safe project-relative
folder:

```text
main.acore
AxiomDeps.toml
logic/pricing.rs                 # or pricing.ts / pricing.py
```

`AxiomDeps.toml` maps a stable alias to the source, exports, targets, explicitly
shared source, and maximum requested authority. Axiom generates the private
Cargo wrapper, readable typed bindings, core-Wasm module, package, signatures,
package lock, authority lock, and target policies. Local signing keys are
Axiom-managed, ignored, stored with restrictive permissions, and reused so an
unchanged release is stable.

```bash
axiom extensions source-release checkout \
  --deps AxiomDeps.toml \
  --application example.extensions.checkout

axiom run main.acore --target web
axiom run main.acore --target android
axiom run main.acore --target ios
```

Normal target runs consume the verified `AxiomExtensions.toml` workflow. They
do not require an author-owned Cargo project, FFI adapter, package builder, or
host glue. Third-party crates, npm packages, and pure-Python wheels are declared
with exact versions under the extension; authors do not maintain Cargo
manifests, `package.json`, lockfiles, requirements files, or virtual
environments.

The repository includes a repeatable, generated acceptance fixture for the

```bash

```

The shopping example creates and verifies the signed local release, checks the
Acore source on web, Android, and iOS, exercises Inspector, and proves that the
typed Rust pricing patch is capability-scoped. Separate compact TypeScript and

## Shared data contracts

The Rust schema helper (including its Wasm feature) and generated portable
TypeScript helper consume selected canonical descriptors. Guest validation remains
advisory: the broker/host independently validates results and proposals. Typed
failure payloads are checked before public projection. Private configuration and
opaque secret handles are never guest values.


## Owned operations

The versioned named guest group descriptor has an explicit adapter capability and initially accepts granted contract queries. Ordered effect plans retain their sequential meaning. Group cancellation drains started work before resume; guests cannot expand root budgets or retry/scheduling authority. See [sandboxed owned operations](/acore-language/owned-operations#sandboxed-extensions).


Backend [`batchPolicy`](/reference/typed-request-batching) aggregation is a host
facility under explicit deployment grants and owned operation context. Existing
`Batch` capability declarations alone do not implement aggregation or grant a
private batch operation. A guest receives only selected generated or explicit
granted interfaces. Real-guest tests and generated SDK batch helpers remain
separate qualification gates for the candidate toolchain.

### Bounded stream decoder candidate

The candidate Rust SDK's `Stream<T>::bounded(handle, max_events, max_bytes)`
checks the stream handle and generation, at most 256 events, at most 64 KiB,
bounded nesting, and contiguous sequence numbers before publishing a decoded
batch. A malformed payload leaves sequence progress unchanged. A terminal
handle rejects further batches.

`decode_batch` rejects reported event loss. `decode_state_batch` is the explicit
replaceable-state consumer API and returns `StreamBatch<T>` with `dropped` and
`terminal` metadata. It does not authorize host coalescing, grant a subscription,
or certify a durable cursor. Host authorization, generation retirement and
source capabilities still apply independently. Candidate decoder checks and
real-guest/editor qualification are tracked separately from previously qualified SDKs.

## Candidate selected extension interfaces

The candidate source toolchain accepts a project-relative `interface` JSON file
in a source extension declaration. It selects named pure input/output types for
the declared exports and requested host operations. It cannot add an export,
host operation, permission or target. The sealed output uses
`axiom-sdk-interface-ir/v2` and `axiom-sdk-interface-artifact/v2`; existing
unselected interfaces retain their v1 representation.

```toml
[extensions.tools]
language = "rust"
source = "logic/tools.rs"
interface = "logic/tools.interface.json"
exports = ["normalize"]
targets = ["server"]
```

`tools.interface.json` can select this complete pure value boundary:

```json
{
  "format": "axiom-extension-selection/v1",
  "types": {
    "Draft": {
      "kind": "record",
      "fields": [
        {"name": "title", "valueType": {"kind": "scalar", "value": "string"}},
        {"name": "offset", "valueType": {"kind": "scalar", "value": "signed64"}}
      ]
    }
  },
  "exports": [
    {"name": "normalize", "input": {"kind": "named", "value": "Draft"},
     "output": {"kind": "named", "value": "Draft"}}
  ],
  "imports": []
}
```

Generated Rust adapters provide records, variants, checked ABI codecs and an
export trait. A normalizer uses ordinary typed fields:

```rust
use crate::axiom_bindings::selected::{
    SelectedExports, SelectedExtension, Type_Draft as Draft,
};
use axiom_extension_sdk::{boxed_extension, Extension, Result, TypedInvocation};

struct Tools;
impl SelectedExports for Tools {
    fn normalize(&mut self, mut input: Draft, _: &TypedInvocation) -> Result<Draft> {
        input.title = input.title.trim().to_owned();
        Ok(input)
    }
}
pub fn axiom_extension() -> Box<dyn Extension> {
    boxed_extension(SelectedExtension(Tools))
}
```

The generated TypeScript bindings expose a checked immediate-export wrapper:

```typescript
import { defineSelectedExtension } from "@axiomcore/extension-bindings";

export default defineSelectedExtension({
  normalize({ input, complete }) {
    return complete({ ...input, title: input.title.trim() });
  }
});
```

The restricted Python compiler preserves the same selection while lowering the
function into the checked managed entry point. Generated stubs describe the
dictionary input and completion payload:

```python
from axiom_extension_sdk import extension
from axiom_bindings import Context_normalize

@extension.export
def normalize(context: Context_normalize):
    draft = context.input
    return context.complete({
        "title": draft["title"].strip(),
        "offset": draft["offset"],
    })
```

Records reject missing/unknown fields and noncanonical ABI field order.
Variants require exactly the selected case and payload. Signed positive numbers
retain the signed ABI tag. Managed number profiles reject integers outside the
exact JavaScript range; Rust retains exact 64-bit integers. Pure values have
finite nesting/work, a 64 KiB boundary, and at most 256 list/byte items. Host
handles and recursive type graphs are rejected. Scalar/list ports use a named
alias. These checks do not validate host authority or commit proposals; the
broker remains responsible for both.

This candidate profile uses the public Rust SDK 0.1.2 and
TypeScript SDK 0.1.2 source, with Python SDK identity recorded from its actual
locked distribution. Signed native-host tests exercise actual Rust, TypeScript
and Python Wasm guests with checked named continuations. Publication and mounted
target/editor qualification remain separate gates.

### Named continuations

A selection can declare a finite continuation with an export, a pure state type
and named branches that refer to already requested call operations. For example,
`load: Key -> Draft` can declare `loaded`, carry `Key` as its state and name a
`catalog.lookup` branch `task`. The corresponding generated TypeScript entry is:

```typescript
import { defineSelectedExtension } from "@axiomcore/extension-bindings";

export default defineSelectedExtension({
  load(context) {
    return context.effects.loaded(context.input, { task: context.input });
  },
  resume: {
    loaded(context) {
      const task = context.outcomes.task;
      if (task.case === "ok") return context.complete(task.value);
      return context.complete({ title: "Safe failure" });
    }
  }
});
```

Rust receives generated `Step_load`, `Calls_loaded` and `Outcomes_loaded` types.
Python uses typed `Context_load` and `Resume_loaded` stubs with
`@extension.export` and `@extension.resume` functions. Selected Python source is
checked by the pinned Pyright checker before restricted AST lowering.

The host owns the invocation identity and validated continuation state. It
checks all branches before dispatch and every outcome before authored resume.
The control descriptor is never dispatched or charged as a host call. A resume
can complete once; a second yield, stale identity, unknown branch or malformed
payload retires the guest. Fresh managed instances recover state from the host
envelope. General async and persistent authored heaps are outside this profile.

Selected packages use `axiom-extension/v3` with the exact signed interface.
The native managed adapter uses a separately identified interpreter budget and
build profile; legacy packages keep their existing profile. The current selected
profile rejects snapshots, patches, transactions and emitted events. Browser
and mounted mobile support requires its own host qualification.

The shared language server completes and navigates the `interface` manifest
field. Explicit SDK preparation emits physical typed helper files for native
Rust/TypeScript/Python tooling. Changing the captured selection invalidates the
prepared interface; passive editing never runs a guest or grants permission.
