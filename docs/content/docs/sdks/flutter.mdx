`axiom_flutter` runs the AxiomCore runtime, written in Rust, inside a Flutter
app: through `dart:ffi` on Android, iOS and macOS, and as WebAssembly on the
web. `axiom_flutter_generator` turns a backend `.axiom` contract into a typed
Dart client. The runtime handles HTTP, validation, caching, retries, streams
and auth tokens as the contract declares them; the generated client gives you
Dart methods and classes for every endpoint and model.

New to the SDK? Start with the
[Flutter quickstart](/getting-started/quickstart-flutter). This page is the
reference.

## Platforms

| Platform | Minimum | How the runtime is supplied | Status |
| --- | --- | --- | --- |
| Android | API 24; `arm64-v8a`, `armeabi-v7a`, `x86_64` | `libaxiom_runtime.so` bundled in the package | Alpha |
| iOS | iOS 13 | CocoaPods downloads `AxiomRuntime.xcframework` and verifies its SHA-256 | Alpha |
| macOS | macOS 11 | Same as iOS | Alpha |
| Web | Browsers with WebAssembly; dart2js and dart2wasm | Wasm runtime bundled in the package assets | Alpha |
| Linux, Windows | | No runtime library is published | Not supported |

Platform setup:

- **Android:** set `minSdk = 24`, add `android.permission.INTERNET` to the main
  manifest, and allow cleartext HTTP to `10.0.2.2` in debug builds only if your
  development backend uses plain HTTP. 32-bit `x86` emulator images are not
  supported. No R8 or ProGuard rules are needed.
- **iOS and macOS:** set the deployment target to iOS 13 or macOS 11 in the
  Podfile and in Xcode. macOS apps need `com.apple.security.network.client`
  in both entitlement files. For plain `http://` to a local backend on iOS,
  add `NSAllowsLocalNetworking` under `NSAppTransportSecurity` in
  `Info.plist`. The plugin includes a privacy manifest. If the
  runtime download or checksum check fails, pod preparation keeps the previous
  framework and stops the build.
- **Web:** nothing to add to `web/index.html`. See [Web](#web) for CORS,
  Content Security Policy and cache storage.

## Install and generate

```bash title="Terminal: Flutter project root"
flutter pub add axiom_flutter:^0.150.0 dev:axiom_flutter_generator:^0.150.0
axiom pull ../backend/backend.axiom --framework flutter --name tasks --out lib/axiom_generated
```

`axiom pull` (CLI 0.156.0) copies the contract to `assets/axiom/<name>.axiom`
and registers it in `pubspec.yaml`, adds `axiom_flutter` and the dev
dependency `axiom_flutter_generator` when they are missing, runs
`dart pub get`, and writes `axiom_sdk.dart` and `models.dart` into the output
directory. Pull again whenever the contract changes. Add the packages
before the first pull: when they are missing, CLI 0.156.0 adds
`axiom_flutter` 0.147.5 and `axiom_flutter_generator` 0.146.6, which have no
Android support and lack most of the API on this page. Keep both packages on
the same version.

<Callout type="info" title="Coming in the next CLI release">
  These `axiom pull` and `axiom init` conveniences are not in CLI 0.156.0:
  `--base-url` and `--variant` (stored in `AxiomDeps.toml` and kept across
  re-pulls), a SHA-256 of each pulled contract for release builds,
  `--fix` (sets the iOS, macOS and Android settings listed above), `--watch`
  (regenerates when the contract or a sibling `main.acore` changes),
  `axiom init --template flutter` (backend plus Flutter app), a Flutter
  section in `axiom doctor`, a clear message when `AxiomDeps.toml` is missing,
  and full error output when `dart pub get` fails.
</Callout>

### What gets generated

| Contract item | Dart |
| --- | --- |
| Contract `tasks` | `sdk.tasks`, a module class |
| Endpoint `list_tasks` | `AxiomQuery<models.TaskList> listTasks({...})` |
| Path, query and header parameters | Named parameters; optional ones are nullable |
| Body parameters | Named parameters, sent as one JSON object |
| `Bytes` fields | `Uint8List`, base64 on the wire |
| SSE or chunked stream endpoint | `AxiomQuery<T>` plus `Stream<T> <name>Stream(...)` |
| WebSocket endpoint | `AxiomChannel<Receive, Send> <name>Channel(...)` |
| Model `Task` | `models.Task` with `fromJson`, `toJson` and value equality |
| Union | A sealed class with one subclass per option and an `Unknown` fallback |
| Enum | A Dart enum that keeps the wire value |
| Field rules (`minLength`, ranges, enums) | `<Model>Validators`, one static `TextFormField.validator` per field, plus `all` by wire name |
| `failure` declarations | Sealed failure classes and `when<Endpoint>(...)` helpers on `AxiomError` |
| Endpoint IDs and cache identities | `TasksModule.endpointIds`, `TasksModule.cacheIdentities` |

Every endpoint method also takes `AxiomCallOptions? options`. `POST`, `PUT`,
`PATCH` and `DELETE` endpoints are sent as mutations and never cached.

## Configuration and environments

`AxiomSdk.create()` starts the runtime, checks that the runtime and the package
versions match, loads every contract, and registers typed failures. It throws
when start-up fails, so call it before `runApp`.

```dart title="lib/main.dart (excerpt)"
late final AxiomSdk sdk;

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  sdk = await AxiomSdk.create(
    baseUrlOverrides: {'tasks': 'https://api.example.com'},
  );
  runApp(const App());
}
```

| Parameter | Type | Use |
| --- | --- | --- |
| `config` | `AxiomConfig?` | Replaces the generated `AxiomDefaultConfig.config` (contracts, `dbPath`, `debug`) |
| `environment` | `AxiomEnvironment?` | Named set of base URLs |
| `baseUrlOverrides` | `Map<String, String>?` | Base URL per contract name |
| `assetLoader` | `AxiomAssetLoader?` | Loads contract assets; default `rootBundle` |

The base URL of each contract is resolved in this order:

1. `baseUrlOverrides[name]`
2. `environment.baseUrls[name]`, then `environment.defaultBaseUrl`
3. the build-time defines `AXIOM_ENV` and `AXIOM_BASE_URL`, when no
   environment is passed
4. the generated default: the contract's base URL, the `base_url` of the
   contract's table in the app's `AxiomDeps.toml`, or `http://localhost:8000`

```dart title="Dart excerpt: environments"
const staging = AxiomEnvironment(
  name: 'staging',
  defaultBaseUrl: 'https://staging.example.com',
  baseUrls: {'billing': 'https://billing.staging.example.com'},
);
sdk = await AxiomSdk.create(environment: staging);
```

```bash title="Terminal: build-time base URL"
flutter run --dart-define=AXIOM_BASE_URL=http://10.0.2.2:8080
```

`AxiomSdk.initResult` reports the runtime versions (`runtimeInfo`), each
contract's load status and trust level, and the start-up duration. A version
mismatch between the runtime library and the Dart package fails start-up with
`AxiomVersionMismatch`; upgrade both together. `AxiomSdk.fromRuntime(runtime)`
wraps a runtime you initialized yourself, for tests or custom start-up.

The response cache needs storage. Without `AxiomConfig.dbPath`, the SDK
stores it in the app's application support directory on Android, iOS and
macOS, and in `localStorage` on the web. Set `dbPath` to choose another
directory for cached, recoverable data. The cache is not a credential store.

## Queries

```dart title="Dart excerpt: a query bound to a widget"
AxiomBuilder<models.TaskList, models.TaskList>(
  query: sdk.tasks.listTasks(),
  loading: (context) => const CircularProgressIndicator(),
  error: (context, error) => Text(error.message),
  builder: (context, state, list) => Column(
    children: [
      for (final task in list.tasks) Text(task.title),
      if (state.isFetching) const LinearProgressIndicator(),
    ],
  ),
)
```

`AxiomBuilder` subscribes while mounted and keeps the last data while a
refresh runs. `transform` maps `T` to the UI type `R`, and `selector` limits
rebuilds to the values it returns. You can also use the query directly:

| Member | Use |
| --- | --- |
| `query.stream` | `Stream<AxiomState<T>>` for BLoC, Provider, Riverpod or `StreamBuilder` |
| `query.stream.unwrap()` | `Future<T>` with the first data, or throws the `AxiomError` |
| `onlyData()`, `onData(callback)` | Stream helpers for data events |
| `query.refresh()` | Revalidate from the network |
| `query.prefetch()` | Load once without keeping a subscription |
| `query.cancel()` | Cancel the in-flight request |
| `query.setHeader(name, value)` | Add a header before the stream starts |

`AxiomState<T>` has `status` (`idle`, `loading`, `success`, `error`), `data`,
`error`, `source` (`none`, `cache`, `network`), `isFetching`, `isMutating`
and `isStreaming`, with `isLoading`, `hasData` and `hasError` getters.
Identical queries share one request, and argument order does not change the
cache key.

### Per-call options

```dart title="Dart excerpt: AxiomCallOptions"
sdk.tasks.listTasks(
  options: const AxiomCallOptions(
    timeout: Duration(seconds: 5),
    headers: {'x-request-source': 'pull-to-refresh'},
    cacheMode: AxiomCacheMode.refresh,
  ),
);
```

`timeout` cancels the call and reports `NetworkTimeout`. `headers` are merged
into the request. `AxiomCacheMode.refresh` bypasses cached data for this call
by sending `x-axiom-cache-mode: refresh`.

## Mutations

```dart title="Dart excerpt: a mutation bound to a button"
AxiomMutationBuilder<models.Task, String>(
  mutation: AxiomMutation(
    (title) => sdk.tasks.createTask(title: title),
  ),
  builder: (context, state, execute) => FilledButton(
    onPressed: state.isMutating ? null : () => execute('Write docs'),
    child: Text(state.isMutating ? 'Saving...' : 'Add task'),
  ),
)
```

`AxiomMutation` wraps a function from your argument type to the generated call.
Mutations are never cancelled implicitly; call `query.cancel()` if you need
to. A mutation whose contract lists `invalidates` cache identities refreshes
the matching cached queries in the runtime. To refresh other screens, see
[Cache strategies and control](#cache-strategies-and-control).

## Streams

| Contract streaming | Generated | Notes |
| --- | --- | --- |
| `SseStreamDef` | `<name>()` as `AxiomQuery<T>` and `<name>Stream()` as `Stream<T>` | One typed value per event's `data:` payload |
| `HttpStreamDef` (chunked, NDJSON) | Same as SSE | One typed value per frame |
| `WebSocketDef` | `<name>Channel()` as `AxiomChannel<Receive, Send>` | Bidirectional |

```dart title="Dart excerpt: server-sent events"
final sub = sdk.feed.ticksStream().listen((tick) => print(tick.value));
// later
await sub.cancel();
```

```dart title="Dart excerpt: WebSocket channel"
final channel = sdk.chat.roomChannel();
channel.stream.listen((state) {
  if (state.data case final message?) print(message.text);
});
channel.send(models.Outgoing(text: 'hello'));
// later
channel.close();
```

The channel's `reconnect` parameter defaults to `AxiomReconnectPolicy.auto`
(exponential back-off). Pass `AxiomReconnectPolicy.none` to disable it, or
your own policy with `maxAttempts`, `initialDelay` and `maxDelay`. Cancelling
the last subscription of a stream cancels the request.

## Authentication

Tokens are held in runtime memory only. Restore them from secure storage at
start-up. The SDK sends the token as `Authorization: Bearer <token>`.

Contracts built from an Acore backend carry no client auth metadata, so use a
namespace token, the global token or an auth provider:

| Scope | Call |
| --- | --- |
| Every call of a contract | `sdk.runtime.setNamespaceAuthToken(namespace: 'tasks', token: token)`, or `sdk.tasks.axiom.setNamespaceToken(token)` |
| Every contract | `sdk.runtime.setGlobalAuthToken(token)`, `clearGlobalAuthToken()` |
| Refresh on demand | `sdk.runtime.setAuthProvider((namespace, methodName) async => token)` |
| One auth method | `sdk.tasks.axiom.setAuthToken(methodName, token)`, `clearAuthToken(methodName)`. Only for contracts that declare auth methods |

```dart title="Dart excerpt: bearer token for every call"
sdk.runtime.setGlobalAuthToken(accessToken);

// Or refresh before calls that need a token:
sdk.runtime.setAuthProvider((namespace, methodName) async {
  return await myAuth.freshAccessToken(); // null means "no token"
});
```

A per-method token wins over a namespace token, which wins over the global
token. The auth provider is asked for a token when a call needs one; return
`null` when the user is signed out. The generated `TasksModule.authMethods`
lists the auth methods a contract declares, and is empty for contracts built
from an Acore backend.

Contracts with a cookie session use the runtime's cookie jar on native
platforms; cookie values never reach Dart. On the web the browser owns
cookies (see [Web](#web)).

On logout, call `await sdk.runtime.resetSession()`. It cancels in-flight calls,
clears the session-partitioned cache, active queries and every token set from
Dart, and removes the auth provider. Contracts stay loaded.

For managed sign-in (password, email code, social, MFA) with automatic token
refresh, use [axiom_flutter_auth](/sdks/flutter-auth).

## Cache strategies and control

The contract chooses the caching of each `GET` endpoint with
`cache(strategy: ..., ttl: ...)`:

| Strategy | Behaviour |
| --- | --- |
| `networkOnly` | Always fetches; nothing is served from cache |
| `cacheFirst` | Serves a fresh cached value; fetches when missing or expired |
| `networkFirst` | Fetches; serves the cached value if the network fails |
| `staleWhileRevalidate` | Serves the cached value at once (`source: cache`, `isFetching: true`) and refreshes it |

Control the cache from Dart:

| Call | Effect |
| --- | --- |
| `sdk.tasks.axiom.invalidateIdentity('task.item')` | Refetch active queries whose endpoint declares that `cacheIdentity` |
| `sdk.tasks.axiom.invalidateAll()` | Refetch every active query of the contract |
| `sdk.runtime.invalidate(namespace:, cacheIdentity:, endpointId:, args:)` | The general form of the two calls above |
| `sdk.runtime.setQueryData(namespace:, endpointId:, args:, data:)` | Optimistic update; pushes `data` to listeners, not persisted |
| `sdk.runtime.getCachedQueryData(namespace:, endpointId:, args:)` | Last value held in Dart, or `null` |
| `sdk.runtime.clearCache([namespace])` | Drop cached data and refetch active queries |
| `sdk.runtime.purgeCache([namespace])` | Drop cached data without refetching |
| `AxiomCallOptions(cacheMode: AxiomCacheMode.refresh)` | Bypass the cache for one call |

Use `TasksModule.endpointIds['listTasks']` for the `endpointId` arguments.

## Cancellation and lifecycle

- A query's request is cancelled when its last listener goes away, for example
  when the `AxiomBuilder` is disposed. The last value stays in memory for the
  next listener, which fetches again if the request was cancelled.
- `query.cancel()` and `channel.close()` cancel explicitly. A cancelled call
  completes with `Cancelled`, which is not reported to `onError`.
- `await sdk.runtime.shutdown()` stops the runtime, for example on app exit.
  It is safe to call twice and before start-up. Hot restart works: the next
  `AxiomSdk.create()` starts again.

## Errors and typed failures

Every failed call produces an `AxiomError` with `stage`, `category`, `code`,
`message`, `retryable` and optional `details`. `code` is a sealed
`AxiomErrorCode`, for example `ValidationError`, `NetworkTimeout`,
`NetworkConnectionFailed`, `AuthTokenExpired`, `NotInitialized`, `Cancelled`
or `HttpStatus(code)`. Builders receive it in `error:`, and `unwrap()` throws
it. See [Runtime errors](/reference/error-codes#dart-error-types) for the full
list.

A contract `failure` (for example a 409 with a body) becomes a typed Dart
class. Match it with the generated helper:

```dart title="Dart excerpt: typed failure"
try {
  await sdk.tasks.claim(name: 'docs').stream.unwrap();
} on AxiomError catch (error) {
  final text = error.whenClaim(
    conflict: (failure) => 'Already claimed as ${failure.existingId}',
    orElse: (other) => other.message,
  );
  showMessage(text);
}
```

`error.contractFailure` returns the failure object or `null`, and
`error.failureCode` and `error.failurePayload` give the raw values.

For a global handler, listen to `sdk.runtime.onError`. Each `AxiomErrorEvent`
has `error`, `namespace`, `endpointId` and `requestId`.

## Signed and hash-locked contracts

By default the generated client loads contracts unsigned, and the runtime
logs a security warning in debug mode. To verify contracts:

- Add `signature` and `public_key` to the contract's table in the app's
  `AxiomDeps.toml` before you pull, or set `signature` and `publicKey` on
  `AxiomContractConfig` yourself. A partial or invalid pair fails start-up; it
  never falls back to unsigned mode.
- With a signature, a public key and a `sha256` for every contract, the
  generated config uses the hash-locked load and `requireSignedContracts` in
  release builds only. Debug builds keep the normal load so that re-pulls work
  during development.

`AxiomSdk.initResult.contracts` reports `trust` (`unsigned`, `signed` or
`locked`) for each contract.

## Extensions

On Android, iOS and macOS, `sdk.runtime.loadExtension(package)`,
`invokeExtension(call)`, `extensionLifecycle(event)` and `extensionAudit()`
run sandboxed AxiomCore extensions. A non-zero runtime status throws
`AxiomExtensionException`. On the web the four methods throw
`UnsupportedError`. See [Extensions](/extensions).

## Observability

- The runtime sends `traceparent` and `tracestate` on every call. Allow both
  headers in your backend's CORS policy for web builds.
- `AxiomConfig(debug: true)` logs each call and response.
- `sdk.runtime.onError` is a single place to report errors to your crash or
  analytics tool.

## Web

- The wasm runtime is loaded from the package assets, so
  `flutter run -d chrome`, release builds, `--base-href` sub-paths and dart2wasm
  (`flutter build web --wasm`) work unchanged.
- Minimum Content Security Policy: `script-src 'self' 'wasm-unsafe-eval'`.
  Build with `--no-web-resources-cdn` to serve CanvasKit from your origin, or
  also allow `https://www.gstatic.com`. A restricted `connect-src` must include
  your origin and every backend URL.
- **CORS.** Calls are ordinary `fetch` requests from your page's origin.
  Allow every origin you serve from, port included (pass `--web-port` to
  `flutter run`). The SDK sends `accept`, `traceparent` and `tracestate` on
  every call, so allow at least `accept`, `content-type`,
  `x-axiom-request-id`, `x-axiom-cache-mode`, `traceparent` and `tracestate`,
  plus `authorization`, your API key header and any header you pass in
  `AxiomCallOptions.headers`. A missing header makes the browser's preflight
  fail with 403 and the app shows no data. A rejected origin shows up as a
  network error, not an HTTP status.
- Cookie sessions need `credentials: true` and an explicit origin.
- Browsers cannot set `Authorization` on a WebSocket handshake, so a WebSocket
  endpoint behind a bearer guard cannot be reached from the web. With CLI
  0.156.0, a global `cors(...)` policy also makes `axiom run` refuse WebSocket
  upgrades.
- The response cache uses the page's `localStorage` (per origin, shared by
  tabs) and falls back to memory when it is unavailable. `dbPath` is ignored.

## Performance

Each call crosses from Dart into the native or wasm runtime. For measured call
overhead, startup time and app size, with the method and devices, see the
[benchmarks in the SDK README](https://github.com/AxiomCore/axiom-sdk#benchmarks).
Measure release builds of your own app before you rely on a number.

## Platform limits

- Linux and Windows have no runtime library.
- Android: no 32-bit `x86`; API 24 or newer.
- Web: no extensions; WebSocket auth limits above; `Int64` values above
  2^53 lose precision because the browser parses JSON numbers as doubles.
- `--framework dart` is accepted by `axiom pull`, but it does not add packages
  or copy the contract asset, and this page does not cover it.
- Test release builds on each platform, not only debug and hot reload.
