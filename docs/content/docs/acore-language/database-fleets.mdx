title: Database fleets
description: Frozen tenant inventories, release-bound review, offline promotion and resumable Acore database delivery.
---

The experimental `database-experimental-offline-fleet/v1` profile deploys
already enrolled PostgreSQL and SQLite targets using their existing signed
histories. Developers author desired Acore state; migration SQL and durable
delivery artifacts stay private below `.axiom/database/v1/` or in private CI
artifacts. MySQL/MariaDB remain later adapters.

Freeze an explicit private inventory before review. Every member selects a
tenant ID, stage, engine, instance budget, group, signed bundle and target
binding. Canary failure blocks dependent groups. A changed inventory or budget
requires a new freeze and review. The first scheduler executes one target at a
time, below every declared instance budget; the fleet has no shared database
transaction.

```sh
axiom database fleet prepare --inventory .axiom/database/v1/inventory.json \
  --policy .axiom/database/v1/policy.json --out .axiom/database/v1/fleets/release
axiom database fleet inspect .axiom/database/v1/fleets/release
axiom database fleet approve .axiom/database/v1/fleets/release \
  --reviewer owner --kind source --key-file /private/owner-key.json
axiom database fleet approve .axiom/database/v1/fleets/release \
  --reviewer security --kind security --key-file /private/security-key.json
axiom database fleet approve .axiom/database/v1/fleets/release \
  --reviewer operations --kind operations --key-file /private/operations-key.json
axiom database fleet verify .axiom/database/v1/fleets/release \
  --trusted-policy-sha256 "$REVIEWED_POLICY_SHA256"
axiom database fleet run .axiom/database/v1/fleets/release \
  --inventory .axiom/database/v1/inventory.json \
  --providers /private/providers --journal .axiom/database/v1/fleets/dev-journal \
  --stage dev --receipt-key /private/operations-key.json \
  --trusted-policy-sha256 "$REVIEWED_POLICY_SHA256"
```

Set `REVIEWED_POLICY_SHA256` to the reviewed canonical policy digest in protected
operator or CI configuration. An artifact's own keys/digests are not independent
trust. Source-owner, security and operations reviews bind the exact artifact,
typed evidence and expiry. Renewed reviews append immutable evidence.

The private inventory uses `axiom-database-fleet-inventory/v1`; the policy uses
`axiom-database-fleet-policy/v1`. Unknown fields and untyped URL/SQL templates
fail. Policy fields include `reviewers`, exact `sourceOwners`,
`securityReviewer`, `operationsReviewer`, `denyOperations`,
`maxAffectedObjects`, `maxStatementSeconds` and `resumePending`.
`resumePending` explicitly authorizes continuation of supported native
PostgreSQL checkpoints; special index repair remains a separate signed native
operation. Target enrollment and planning still use the individual dialect
commands from [database contracts](/acore-language/database-contracts)
and [SQLite contracts](/acore-language/sqlite-contracts).

For a schema tenant, `fleet expand SOURCE --schema app --tenant tenant1
--sql-name tenant_one --out PRIVATE_PROJECT` changes one parsed literal schema
name, recompiles it, preserves logical IDs and records digests. Plan and sign
that expanded project before freezing it. This slice accepts core local
PostgreSQL templates; opaque/advanced definitions and imported package templates
require explicit authoring. There is no deploy-time SQL substitution.
Independent schemas in one physical database use one aggregate contract and
revision scope; separate databases are independent fleet targets.

Rerunning freshly verifies native accepted heads and skips completed work,
including a commit whose fleet acknowledgement was lost. A partial fleet exits
nonzero and retains masked per-target outcomes. Supported PostgreSQL data
transforms preserve their signed batch limits and durable per-target cursors;
reports expose bounded progress counts and no row values. Monitoring never
turns itself into a migration or writable SQLite journal-recovery operation.

`fleet export` transports identical private bytes and reviews without cloud
login. `fleet promote --receipt FILE --to staging` requires a fresh complete
signed dev receipt, the operations key, trusted policy digest and `--out` path.
Staging execution requires that promotion via `--promotion`. Promotion to
production requires the exact D9 profile, current deployment recovery receipts
and one-hour production admission. Promotion does not replan or retarget history.

`fleet monitor` uses the same inventory/provider/journal/stage/receipt-key/trust
arguments as `run` and returns fresh drift/history outcomes without applying
DDL. `fleet dashboard ARTIFACT --out FILE.html` writes a local masked impact and
column dependency view with no external assets. Opaque SQL lineage and runtime
backend/frontend consumers remain unknown.

`fleet ci`, `fleet operator` and `fleet terraform-apply` call the same Rust
state machine as `run`. `fleet terraform-plan` emits a flat string map for
Terraform's external-data protocol without migration authority. These entry
points support an Axiom controller or explicit CI/Terraform jobs; no Kubernetes
controller, Terraform provider plugin or hosted registry is installed by this
experimental profile. Discovery is bounded local-file resolution. Arbitrary
shell hooks, HTTP/SQL discovery and unbounded data-report scripts remain gated.


## Named PostgreSQL production admission

D9 qualifies `postgres-17.11-darwin-25.2-arm64-file/v1`: self-managed PostgreSQL
17.11, UTF8/libc C/C, macOS 26.2 (Darwin 25.2.0) arm64, locked Rust 1.93 native
CLI, explicit verified-TLS CA and private file providers. Qualification belongs
to the release's recorded executable SHA-256. Another build, engine patch,
operating system or hosted provider needs separate qualification. SQLite retains
its experimental gate.

Before production, quiesce the clean enrolled checkpoint, take and verify an
actual physical backup, retain its WAL, restore to a named point on an isolated
server and prove the exclusion of a later committed transaction. Keep backup,
WAL, restoration, isolation/fencing and recovery-point logs in private operator
storage. The closed provider record binds those evidence digests, observation
time and measured RPO/RTO. A reversible SQL flag cannot replace restoration.

```sh
axiom database fleet recovery-check /private/fleet/release \
  --member tenant_one --restored-binding /private/tenant-one-restored.json \
  --providers /private/providers --provider-evidence /private/provider-evidence.json \
  --trusted-policy-sha256 "$REVIEWED_POLICY_SHA256" \
  --key-file /private/operations-key.json --out /private/tenant-one-recovery.json
axiom database fleet admit-production /private/fleet/release \
  --recovery /private/tenant-one-recovery.json \
  --trusted-policy-sha256 "$REVIEWED_POLICY_SHA256" \
  --key-file /private/operations-key.json --out /private/production-admission.json
axiom database fleet run /private/fleet/release \
  --inventory /private/inventory.json --providers /private/providers \
  --journal /private/production-journal --stage production \
  --promotion /private/production-promotion.json \
  --production-admission /private/production-admission.json \
  --receipt-key /private/operations-key.json \
  --trusted-policy-sha256 "$REVIEWED_POLICY_SHA256"
```

Supply one distinct `--recovery` receipt for every production member. Comparison
checks physical identity, ledger incarnation/head, ownership and ordinary
managed heap rows with fixed output settings; a same-server alias, mismatched
data, pending checkpoint or inaccessible RLS subset fails. It does not compare
foreign data, sequence counters, materialized results, credentials or provider
jobs. Application writes must be quiesced by the operator.

Admission binds the exact artifact, inventory, independently pinned policy,
executable and receipts. Provider/restore evidence is valid for at most 24 hours
and requires measured RPO ≤60 seconds and RTO 1–300 seconds; admission lasts at
most one hour. Production supports up to eight targets with serial scheduling,
1,000 affected objects and 30-second statement timeouts. Restore comparison caps
32 ordinary heaps, 10,000 rows, 64KiB per row and 16MiB row input per target.
These are implementation ceilings; the measured two-tenant users/tasks fixture
and retained feature drills do not establish arbitrary workload SLOs.

Every executing/status-verifying production connection must be a durable TLS
primary with data checksums, fsync, full_page_writes, synchronous_commit=on,
wal_level=replica and currently successful physical WAL archiving. Admission
cannot override drift, ownership or native pending-state checks. A failed
canary blocks dependent tenants; partial/nonzero results never mean convergence.
Rerun the exact admitted artifact to freshly verify and skip committed work.

Operators own archive retention, backup verification, isolation, fencing and
routing. During failover, replay the protected LSN and fence the old primary
before promotion/routing. Rotate credentials by updating PostgreSQL and the
private provider file, then verify fresh connections. Cloud CI may copy private
bytes or orchestrate this exact native runner; other cloud runtime/provider
profiles remain unqualified.

For an experimental 17.5 installation, preserve the old signed history and
backups, follow PostgreSQL patch/security/reindex guidance and transfer schema
and data to an isolated 17.11 target excluding the old `_axiom_database` ledger.
Verify data equivalence, adopt the exact schema, enroll new authority, then
replay/review/recover/admit. D9 does not silently repin or transplant old ledgers.
Backend queries/pools, full application rolling compatibility and complete
PostgreSQL/Atlas property coverage retain separate gates.
