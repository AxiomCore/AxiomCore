Use this reference when a feature's exact support boundary affects your
application. The [support matrix](/introduction/support-matrix) is the short
entry point; the entries below retain the detailed qualifications.

The general support baseline was reviewed on September 22, 2026, database
qualifications on October 5, and advanced language qualifications on October
7-8. These historical qualifications are not a statement that every feature
ships in the newest public binary. The first-app walkthrough separately tests
published CLI 0.149.0 and signed web host 0.6.12 on macOS arm64.

## Language, contracts, and packages

| Capability | Status | Exact boundary |
| --- | --- | --- |
| Acore language toolchain | **Alpha** | Parser, evaluator, standard library, diagnostics, and language-server foundations. |
| managed language foundations | **Experimental** | Compatible compiler and matching native server runtime: bounded shared validation/codecs, selected typed failures, finite managed branches/await, private typed configuration and purpose-bound secrets, owned cleanup and explicitly prepared PostgreSQL transactions. Web owners and verified Rust/Wasm guests use selected checked helpers. Worker, generated mobile readers, editor versions and distribution retain their separate capability gates. |
| owned concurrency, operation policies and timing | **Experimental** | Compatible compiler/native host: finite named read groups, typed collected outcomes, cancellation/drain, root budgets, provider-attested retry policies and typed durable enqueue through an explicit reviewed controller. Redis recovery and composed job/provider attempt bounds have separate native fixture evidence. Web and generated mobile owners support bounded foreground polling/debounce; mobile activation requires the explicit foreground-events host capability. Compiled lifecycle queues and generated owner tests do not certify a mounted mobile application. Rust/Wasm query groups require a group-capable trusted broker adapter; other SDK/host profiles reject unsupported groups. Installed editor and public binary publication retain exact-toolchain gates. |
| .axiom service contracts | **Alpha** | Build, inspect, semantic diff, local test/mock, release, pull, and runtime workflows. |
| advanced application candidate | **Experimental** | Matching source compiler/native host: bounded authority-partitioned read caching, typed read batches, managed finite snapshot streams, qualified receipt-backed archive batches, inherited form rules and selected failures, runtime-owned submission identity, and generated selected Rust/TypeScript/Python codecs with finite named reentry. The complete task source combines signed pure guest computation, managed PostgreSQL receipt/outbox writes, cache invalidation and bounded snapshot reduction. Reports bind actual execution level, artifact hashes, assertions and cleanup. Actual durable-provider and mounted web fixtures remain distinct from scripted/generated mobile adapters; exact installed editor delivery, wider target qualification and public artifact promotion retain separate gates. |
| observability, scenarios and delivery | **Experimental** | Exact source-linked private observations; opt-in typed public/private/secret telemetry fields with redaction; strict artifact-bound native scenarios with logical retry and batch-window barriers, cancellation and cleanup; explicit synthetic credential/provider expiry environments that cannot activate in production. Reference frontend scenarios virtualize polling and stream windows; native OS containment and actual provider recovery retain distinct real-time gates. The playground task/inventory examples include editable database contracts/manifests and live checked table previews. Matching CLI/LSP, VS Code/Zed adapters, compiler and host readers are required. |
| Typed package envelope | **Alpha** | Service, theme, component-library, database-schema, extension, and application-policy kinds with canonical encoding and validation. |
| Theme and component packages | **Alpha** | Typed exports, targets, roles/props/slots/composition constraints, lock resolution, and semantic change classification. |
| Executable extensions | **Experimental** | Typed Rust, managed TypeScript/Javy, and restricted Python AOT source profiles lower to one WebAssembly ABI, signed authority locks, and bounded broker. Supported third-party package forms are deliberately narrow and pre-stable. |
| Axiom Inspector | **Alpha** | Canonical application evidence, semantic graph queries, authority and security review, normalized runtime sessions, snapshot/diff/impact, agent output, and a secure local dashboard. |
| Jev question planner | **Experimental** | Opt-in bounded intent and selector planning through Vercel AI Gateway. Local Inspector evidence remains authoritative; remote planning can abstain. |

semantic diff for every contract or package upgrade.

## Database developer workflow

CLI 0.149.0 adds explicit Acore contract identity/version, native PostgreSQL/SQLite connections, atomic versioned migration/compensation, status/history/comparison, noninteractive preparation/frozen promotion, a native SQL console and source-owned private mappings. Default Axiom-generated artifacts/locks/reports are hidden. The playground compiles matching metadata and simulates versioned transitions with retained valid rows and clean downloads.

The developer adapter accepts PostgreSQL 17/18 and SQLite 3.37+ on declared Unix platforms. A distribution must include a validator for the target PostgreSQL major or find a matching qualified installation internally. A PostgreSQL distribution needs its accepted validator assets for the selected major and platform. Windows, generic hosted-provider capabilities, nontransactional stages and advanced application codecs/receipts retain their own qualification gates. Historical certified recovery/production profiles remain unchanged.
